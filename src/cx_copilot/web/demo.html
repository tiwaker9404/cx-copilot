Customer message
Pick an example or write a ticket. The result shows how it was triaged, whether a person needs to step in, the reply, and which policies it was allowed to use.
What happens on every ticket
  1. PII is redacted, then the ticket is triaged (category, urgency, sentiment).
  2. Danger, legal threats, fraud, angry + urgent, or a third message about the same problem go to a person. Code decides that, not the model.
  3. Relevant policies are retrieved and a reply is drafted from them.
  4. A QA check rejects any timeline, refund, credit, upgrade or "I've escalated this" that the policy notes don't back. The draft gets one retry with the reasons, then the ticket is escalated: a holding reply beats a wrong one.
